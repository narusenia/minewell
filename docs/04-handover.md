## 今どこまで動くか

```rust
struct Arena { #[nbt(rename = "Radius")] radius: f64, name: String, keeper: Option<i32> }

fn area(r: fix<1000>) -> fix<1000> {
    let pi = fix::<1000>(3142);
    return pi * r * r;              // スケール補正は自動
}

fn keeper_of(a: Arena) -> Option<i32> {
    let id = a.keeper?;             // 無ければここで抜ける
    return Some(id * 2);
}

#[load]
fn setup() {
    let arena: Arena = nbt!({ Radius: 8, name: "pit" });   // keeper は書かない = None
    let size = area(fix::<1000>(arena.radius));            // data get ... 1000
    if size > fix::<1000>(200000) { say("a big arena"); }
    if arena.name == "pit" { say("the pit is open"); }
    match keeper_of(arena) {
        Some(id) => { say("has a keeper"); }
        None => { say("nobody minds it"); }
    }
}
```

`break`・`continue`・`return` / 関数・引数・戻り値・再帰（相互再帰含む）/
`as`・`at`・`for` と `#[ctx]` 検査 / セレクタ・`pos!`・リソースロケーション /
toolchain 由来のコマンド呼び出し / `#[tick]`・`#[load]` タグ / `data/` パススルー /
存在しない関数参照の検出 / debug の行番号コメントと実行者ガード /
`struct`・フィールド読み書き・`#[nbt(...)]`・`enum`・`match` /
`Vec<T>`・`for x in vec`・ジェネリクス（単相化）・`impl` の固有メソッド・`&`/`&mut` /
`raw!` の補間・`text!`・`#[test]` と `mwl test` / `target/cost.txt` /
CLI（`new`・`check`・`build`・`test`・`install`・`toolchain list|add`）/
エディタのハイライト（tree-sitter と TextMate）。

M9-5〜M9-7 で足したもの（**release のみ**。debug は要件定義 §15 のとおり無最適化）:
**定数畳み込み**（`2 + 3 * 4` → `14`。両端が定数の `fix` 変換も消えた）・
**デッドコード除去**（function タグから辿れない関数と、誰も名前を書かない objective を
出力しない）・**レジスタ再利用**（`<ns>.t` のフェイクプレイヤーが式ごとに増えなくなった）。
併せて **M8-6 の無駄を直した**（ブロック内の束縛を、そのブロックを通らない経路でも
退避していた）。こちらは**両方のプロファイル**で効く。

M9-4 で足したもの:
**`text!`**（連結・自動変換・色・装飾）。**コマンド 1 つ、実行時コストはゼロ** —
JSON が score と storage を直接指せるので、`raw!` と違ってマクロ関数が要らない。

M9-3 で足したもの:
**`raw!` の補間**（`{名前}`、`{{` / `}}` で文字そのもの）。セレクタは無料、
`i32` / `bool` / `String` は**その行だけを本体に持つ補助関数**へ落として昇格。

M9-2 で足したもの:
**`debug_assert!(c, "m")` と `o.expect("m")`**。debug は `tellraw` で場所付きの報告、
**release は文ごと落とす**（条件の評価もテンポラリの確保も起きない）。

M9-11 で足したもの:
**エンティティ NBT のビュー**（`#[entity] struct` と `Mob::of(@s)`、読み書き、単一対象の検査）。

M9-1 で足したもの:
**`Option<T>`**（`Some` / `None` は**パスの有無**）/ **`match` と `if let`** /
**`?` と `-> Option<T>`**（`return fail` と `execute store success ... store result`）。

M8 で足したもの:
**`fix<S>` と const ジェネリクス**（スケール補正・単相化）/
**NBT 相互運用型**（`i8`・`i16`・`i64`・`f32`・`f64`）/
**score ↔ storage の往復**（`fix::<S>(場所)` と `.as_f64()` 等、スケール付き）/
**`String`**（`len`・定数 `slice`・比較・連結）/ **`nbt!`**（型と照合）/
`pos!` の負のオフセット（`~-1`）。

動かないもの: ブロックの NBT と座標（`positioned` / `if block` / raycast）・
`enum` のジェネリクス・`text!` のイベント（`.on_click` / `.on_hover` / `translate!`）・
コマンド引数への実行時値（`raw!` の補間が逃げ道）・`mwl toolchain install`・LSP。

**意図して入れていないもの**（診断が理由を言う）:
`struct`/`enum` を関数の戻り値にすること（バニラの戻り値は整数 1 つ）、
compound どうしの `==`、タプル型バリアント（`V(i32)`）、
浮動小数点リテラル（`nbt!` の中も含め、実数は `fix<S>` が持つ）、
`Option<Option<T>>`（パスの有無は 1 段しか区別できない）、
`#[nbt(optional)]`（欠けうるものは `hp: Option<i32>` と型に書く）、
`enum` のジェネリクス（`Option` が組み込みになった以上、使い道が無い）。

## v1 で確定した設計（マイルストーン順）

以下は各タスクで決めたことの要約。**経緯はここにしかない**ものだけ残してある。

**M9-8〜M9-10**（仕様 §3.23・§6.36・§6.37）:

- **コスト計算は「1 命令 1 コマンド」の建て付けがそのまま効く。** `inst_cost` は
  `emit::command` の入れ子と 1:1。`execute … run` が 2、`$` のマクロ行が 1。
  **ガードは通る前提**で数える（`maxCommandChainLength` が気にするのは最悪値）
- **`+` は「1 周分」の印。** ループ・再帰に加えて**複数一致しうるセレクタの `execute as`**
  も対象。見落とすと `for z in @e[...]` が 1 回分に見える
- **検証は `tinymcf` の実測との突き合わせ。** `examples/arena` の `setup` で
  静的 35 = 実測 35
- **`#[test]` を足した。** 引数も戻り値も `#[ctx]` も取れない。失敗の定義は
  「`debug_assert!` の報告が出たか、インタプリタが診断を出したか」。
  **バニラに実行の中断が無い以上、テストは止まらず走り切って報告だけ残す**。
  テストごとにインタプリタを作り直す。**release には出力されない**（DCE が落とす）
- **宛先駆動は 2 つの形だけに絞った。** 呼び出しそのものと、定数と束縛だけでできた
  算術の連なり。**`let` の新規束縛だけが宛先**（まだ誰も読んでおらず、退避リストにも無い）。
  右に呼び出しがある形と、宛先が被演算子に現れる形は従来どおり
- **期待型を引数にも配った。** `f(nbt!({ .. }))` が書ける

**X-2・X-4・X-6**:

- **toolchain 生成を実データで検証した。** `scripts/build-toolchain.sh 1.21.4` で
  Mojang の data generator を実際に走らせ、**`examples/arena` が実物のコマンド表で
  そのまま通った**（出力は手書き toolchain と 1 バイトも変わらない）。
  M6 の「版差は toolchain が持つ」設計が実データで裏付けられたのはこれが初めて
- ワークフローは **`workflow_dispatch` のみ**。server.jar のダウンロードと
  リリース作成が push で起きてよいことではない
- **ベンチマークは `cost.txt` の表を `insta` で撮るだけ**にした。追跡の仕組みを別に作らず、
  lowering を変えると差分が出る形にしてある。**レビューがそのまま追跡**
- **tree-sitter grammar の山場は `if x { }` と `Point { .. }`**。実パーサは
  `no_struct_lit` フラグで解くが、tree-sitter では `conflicts` に登録して
  `prec.dynamic` でブロック側を勝たせた。型名は**ノードで包まず `alias`** する —
  包むと「識別子か型名か」を `::` の前に決めさせられて `Threat::Calm` が読めない
- **生成物（`src/parser.c`、580KB）はコミットしない。** `mise run grammar` で作る。
  そのタスクが `examples/` を全部パースする grammar のテストでもあり、`ci` に入っている

**M9-4 で確定した設計**（仕様 §3.22・§6.32）:

- **`text!` は parser が式として読む**（`debug_assert!` と同じ）。だから
  `"a".red().bold()` が素の構文で通り、HIR がトークンを手で解析せずに済む
- **連結は `{"text":"","extra":[…]}`。** 先頭を空にしないと、リストの先頭要素の装飾を
  後続が受け継いで `text!("a".red(), "b")` の `"b"` まで赤くなる
- **`crates/mwlc/src/names.rs` を足した。** フェイクプレイヤー名・`mw.vars` のパス・
  objective・storage の id をここで決め、mir と emit と HIR がそこを見る。
  **JSON の中の名前が出力とずれると、バニラは黙って何も表示しない**ので、
  定義を 2 か所に置かない
- **書けるのは束縛そのものだけ。** `m.hp` は先に `let` で受ける。場所のパスを組み立てるのは
  MIR の仕事で、`text!` は HIR に閉じている。必要になったら `place_path` を
  共有する形で広げられる
- **`fix<S>` は拒否する**（M9-3 の `raw!` と同じ理由）
- **イベントは入れていない。** クリックとホバーの JSON は 1.21.5 で形が変わっており、
  版差は toolchain が持つもので、コンパイラに埋め込むものではない。要件定義 §10.3 に明記済み
- 装飾メソッド名は予約。同名の固有メソッドは書けない

**M9-3 で確定した設計**（仕様 §3.21・§6.31）:

- **昇格は補助関数に閉じる。** `$` の行を持つのは生成した `raw_<n>` だけで、
  `raw!` を書いた関数もその呼び出し側もマクロ関数にならない。
  だから **`#[tick]` / `#[load]` の検査は要らなくなった**
- **要件定義 §10.1 を更新した。** 元は「関数そのものを昇格させ、タグの関数が昇格したら
  エラー」だったが、その案は**局所変数を補間できない** — `let x = f();` の `x` は
  呼び出し側が知らないので `mw.args` に書ける者がいない
- **`{` はつねに補間の始まり。** `{{` / `}}` で文字そのもの。生コマンドは NBT の `{...}` を
  書くことが多く、「名前として解決できなければ文字面」に逃がすと綴り違いが黙って通る
- コストは実行時の値 1 つにつき 4 コマンド（マーシャルの `execute store result … run` が 2、
  呼び出し 1、マクロ行 1）

**M9-2 で確定した設計**（仕様 §3.20・§4.21・§6.30）:

- **release は文ごと落とす。** 出力から命令を消すのではなく MIR に降ろさない。
  だから「release に assert が無い」は grep ではなく**コマンド数**で確かめられる
- `debug_assert!` は**パース時に式として読む**。`raw!` のようなトークン列ではないので、
  型検査もそのまま効く
- 報告の場所は emit が span から作る（ソース文字列を持っているのが emit だけ）。
  そのために `command()` が `&Options` を取るようになった
- `mir::lower` は `debug: bool` を取る。emit の `Profile` を mir から参照すると
  依存が逆向きになる

**M9-11 で確定した設計**（仕様 §3.19・§4.20・§6.29）:

- **ビューは値ではない。** `Type::View` はコンパイル時のみで、束縛は場所の別名。
  借用と同じ `place_aliases` に乗り、`let` 自体は文にならない
- **データ命令は `DataRef`（対象 + パス）を持つ。** storage と entity の違いはここだけ
- **スケールはタグが決める。** `fix<S>` が float / double タグなら実数、整数タグなら生の単位。
  storage でも entity でも同じ規則（仕様 §4.16）

**M9-1 で確定した設計**（仕様 §3.18・§4.19・§6.28）:

- **`Some` / `None` はパスの有無。** タグ付き compound にすると、バニラが書いた NBT の
  「欠けているフィールド」を `None` として読めなくなる。ここが設計の要
- そのため **`enum` のジェネリクスは要らなくなった**。`Option<T>` は `Vec<T>` と同じ
  内部化された組み込み型
- **`?` はレジスタに開ける**ので中身は score に載る型に限る。compound は `match` で開ける
- **`match` / `if let` は場所でなくてよい。** `Option` を返す呼び出しは成功フラグと結果の
  2 つで答えるので、compound を照合する `enum` と違って storage に置く必要が無い
- 制御レジスタに `4`（失敗して抜けた）を足した。`3` と同じ経路で伝播する
- **tinymcf: 無いパスの読みは診断を出さない**（SPEC §4.2）。未設定の score が条件を
  偽にするのと同じ。**複数一致は今までどおり診断**

**M8 で確定した設計**（仕様 §3.16〜3.17・§4.14〜4.18・§6.25〜6.27）:

- **`fix<S>` の表現は `i32` と同じ。** 違うのは型だけで、その型がスケールを持つ。
  MIR も emit も fix を知らない — `*` と `/` の補正は HIR で `/ S` を継ぎ足す形で入れた
- **const 引数は型引数の列に `Type::Fix(Scale::Const(n))` として乗る。**
  単相化の表もインスタンス名（`half_fix_1000`）も型引数と同じ仕組みで動く
- **NBT 相互運用型は型がタグそのもの。** だから `#[nbt(byte)] hp: f64` はエラー。
  タグを選びたいフィールドは `i32` か `fix<S>` で持つ
- `is_storage()` の下に `is_compound()` と `is_storage_scalar()` を置いた。
  「storage にある」と「compound である」は M7 まで同じ意味だったが、もう違う
- **文字列の比較は照合**（`execute if data ... {キー:"値"}`）。相手が実行時の文字列なら
  マクロ昇格。**リテラルの部分はマクロの値に直接埋め込む**ので引数が減る
- `nbt!` は書き込み先の型と照合する。接尾辞（`20f`）も小数も書かせない

**まだ効いている落とし穴:**

- **storage に新しく物を置いたら、必ず再帰の退避対象（`live_slots`）に入れること。**
  固定パスを書かず `data_temp()` から採れば自動的に入る。M8-6 で 1 度踏んだ
- 生成する関数名・NBT キーは**小文字**でなければならない（データパックのパス制約）
- コマンドの綴りは `Signature.parts`（木の順）で組み立てる。リテラルと引数は交互に来る
- **`execute … run <cmd>` は 2 コマンド。** ただし `execute store success … if …`（`run` 無し）は
  1 コマンド。コスト表明は必ず生成物を読んでから書く

## 積み残し（理由つき）

| 項目 | なぜ後回しか | 予定 |
|---|---|---|
| **宛先駆動の式 lowering** | 呼び出し・算術・`&&`・`return <フィールド>` の結果がテンポラリ経由でコピーされ 1 コマンド余分。散らすと一貫性を失うため 1 変更にまとめる | M9-10 |
| **ブロック NBT** | 座標のモデルが要る。`positioned` / `if block` を先送りしているのと同じ理由 | 座標モデルと一緒に |
| **`nbt!` の引数位置での照合** | 期待型を式に配る仕組みが要る。いまは注釈付きの `let` だけ | M9-10 |
| **`match` の控えの省略** | 腕が評価対象を書き換えないと分かれば `mw.tmp` へのコピー 1 コマンドは要らない | M9（最適化） |
| **`v[i].push(x)`**（実行時添字の先） | マクロ 2 回と placeholder が要る。まだ誰も使わない | 必要になった時 |
| **外から呼ぶ関数の宣言**（`pub` / `extern fn`） | release の DCE が function タグから辿れない関数を落とすので、`/function` を手で打つ・他のパックから呼ぶ関数を出力に残す手段が無い。仕様 §3.12 が未定のまま | `mod` / `use` / `pub` と一緒 |
| **`text!` のイベントと `translate!`** | `.on_click` / `.on_hover` の JSON は 1.21.5 で形が変わる。版差は toolchain が持つもので、コンパイラに埋めれば「版非依存」が嘘になる | toolchain がイベントの形を持てるようになってから |
| **`text!` に場所を書く**（`m.hp`） | 場所のパスを組み立てるのは MIR の仕事で、`text!` は HIR に閉じている。いまは `let` で受ければ書ける | `place_path` を共有する形が要るとき |
| **コマンド引数への実行時値** | `raw!` の補間で書けるようになった。コマンド呼び出しの引数に直接書くには、シグネチャごとにどの引数を昇格できるか決める必要がある。エスケープハッチがあるうちは急がない | 必要になった時 |
| **`positioned`/`in`/`if block`/`if predicate`**（tinymcf） | 座標・次元・ブロック・predicate のモデルが要り、まだ誰も使わない | 必要になった時 |
| **`mwl toolchain install`** | X-2 の CI はできたが Release がまだ 1 本も無く、HTTP クライアントを足しても突き合わせる相手がいない | 最初のリリースを切ってから |
| **predicate / loot table の ID 検査** | 実物の `commands.json` は X-2 で入手できるようになった。あとは parser 名ごとの写像を決めるだけ | 必要になった時 |
| **`async`/`trait`/`Result`/ユーザ定義マクロ/借用検査/LSP** | v1 スコープ外。予約語だけ確保済み | v1 後 |

## 実装中に決めた、要件定義に書いていなかったこと

要件定義の「Q&A で決めたこと」からは導けず、実装して初めて必要になった判断。
すべて仕様書に反映済みだが、経緯はここにしかない。

1. **MIR にジャンプ命令を入れない。** ターゲットにジャンプが無いので、辺で繋いだ CFG を
   持つ意味が無い。制御フローは生成関数とガード付き命令の 2 つで表す
2. **制御レジスタは必要なときだけ。** ブロックから制御が抜けないなら `$ctl` は
   1 度も現れない。抜けるかどうかはブロックごとに静的に分かる
3. **`#[ctx]` は宣言のみで推論しない。** 推論だと原因から遠い場所でエラーが出る。
   `raw!` の中身は見えないのでどのみち申告が要る
4. **`at self` ではなく `at @s`。** `self` は M7 の `impl` レシーバに予約済み
5. **`&&`/`||` は右辺が純粋なら短絡させない。** 観測上区別できないので 1 コマンドで済ませる
6. **コマンド引数はコンパイル時の値のみ。** 実行時の値にはマクロ関数が要る（M9）
7. **objective 作成関数 `<ns>:__init` を生成し `minecraft:load` に載せる。**
   objective が無いとバニラが全 `scoreboard` コマンドを拒否するので選択肢が無い
8. **コンパイラにコマンド表を埋め込まない。** 埋め込めば「版非依存」が嘘になる
9. **`fix<S>` の `*` と `/` はどちらも掛けてから割る。** 先に割るとスケールが保とうと
   している桁が消える。代償は `fix<1000>` で絶対値 2 の 21 乗あたりの桁溢れ
10. **`fix<S> + i32` は書けない。** 足すべき値が `1` なのか `S` なのか字面から決まらない。
    倍率としての `*` / `/` だけ混ぜられる
11. **const 引数は `fix<S>` のスケールにしか書けない。** 型としても式の値としても使えない。
    値として読めるようにすると式に定数評価が要り、使い道がまだ無い
12. **範囲式（`a..b`）は `slice` の引数専用。** `Range` という型は作っていない
13. **`Option<T>` はパスの有無で表す。** タグ付き compound にすると、バニラの NBT の
    欠けたフィールドを `None` として読めなくなる。**要件定義 §4.2 の `#[nbt(optional)]` は
    入れず**、`hp: Option<i32>` と型に書かせることにした（属性と型の両方に書かせると
    食い違える。M8-3 の「型がタグそのもの」と同じ判断）**←要件定義の更新が要る**
14. **エンティティ NBT はビューにする。** `#[entity] struct` のフィールドが場所になり、
    値としては存在しない。stdlib 関数（要件定義 §9 の `get_data`）にしなかったのは、
    文字列パスでは**タグもスケールも欠損も検査できない**ため（設計原則 2）。
    **要件定義 §4.6 と §9 を更新済み**
15. **`fix<S>` のスケールはタグが決める。** float / double タグなら実数、整数タグなら
    生の単位。「ビューだから実数」にすると同じ型が置き場所で意味を変えてしまう
16. **`debug_assert!` は止まらない。** バニラに実行の中断は無く、`return` で抜けても
    呼び出し元は進む。報告するだけで、値はそのまま流れる。`expect` も同じ
17. **`raw!` の昇格は補助関数に閉じる。** 要件定義 §10.1 は関数そのものを昇格させる案で、
    そのため `#[tick]` / `#[load]` を弾く規則を持っていた。その案は局所変数を補間できない
    （呼び出し側が値を知らない）ので採らず、**規則ごと不要になった**。要件定義を更新済み
18. **`raw!` の `{` はつねに補間。** 文字そのものは `{{`。「解決できなければ文字面」に
    逃がすと綴り違いが黙って通る（設計原則 2）
19. **生成する名前は `names` モジュールが 1 か所で決める。** `text!` が JSON に書く名前と
    mir / emit がコマンドに書く名前は同じでなければならず、ずれても**バニラは黙る**。
    それまで mir と emit に分かれていた定義をここに寄せた
20. **`text!` のイベントは toolchain の仕事。** クリックとホバーの JSON は 1.21.5 で
    形が変わる。版差をコンパイラに埋めれば「版非依存」が嘘になる（決定 8 と同じ理由）
21. **最適化は release だけ。** 要件定義 §15 が debug に求めているのは
    「ソースと出力が 1:1 で追える」こと。畳み込みも DCE もそれを壊すので、
    `mir::lower` が既に持っている `debug` フラグで切る
22. **DCE の根は function タグだけ、ただし `raw!` の中身は読めないので保守的に残す。**
    多く残すのはファイル 1 つの無駄、消し過ぎは実行時の沈黙
23. **テンポラリの寿命は文。** 生存解析を書かずに済んだのは、MIR にジャンプが無く
    （決定 1）、生成関数が次の文の前に返るから。**巻き戻し 1 行で足りる**
24. **失敗するコマンドを出さないのは最適化ではない。** だから退避リストの絞り込みは
    debug でも効かせる。`#[cfg]` 的な線引きは「読みやすさ」に対してだけ引く

## 見つけたバグ（同種を繰り返さないために）

いずれも**生成された mcfunction を読んで**、あるいは**大きい例を書いて**見つかった。
単体テストは通っていた。

1. **生成ブロックからの `return` が呼び出し元に届かない。** mcfunction の `return` は
   自分が書かれた関数しか抜けない
2. **制御レジスタが呼び出し間で残る。** 最上位まで届いた `return` はレジスタを 3 のまま残す
3. **退避対象に未初期化のローカルが混ざる。** `let rest = f(n-1);` の途中で退避すると
   まだ空の `rest` を読もうとしてコマンドが失敗する
4. **storage のローカルを score として退避していた。** 存在しないスコアを読んで失敗
5. **`match` の腕が評価対象を書き換えると、後続の腕も走る。** 評価対象を `mw.tmp` に
   控えてから判定するように直した
6. **引数の後ろに来るコマンドのリテラルを前に出していた。** `playsound <sound> master <targets>`
   が `playsound master <sound> <targets>` になっていた
7. **リソースロケーションのパスに `.` を含められなかった。**
8. **`pos!` が `~-1` を読めなかった。** `~` `-` `1` の 3 トークンで、1 つの座標として
   読む必要がある。データパックがいちばん書くオフセットなのに、書くと
   「座標が 3 つ要る」という無関係な診断が出ていた
9. **コンパイル時の型を引数とフィールドに書けてしまっていた。** `fn f(s: Selector)` も
   `struct S { p: Pos }` も通り、MIR で `unreachable!` に落ちていた。
   同じ理由で `let z = @e[...];` もコンパイラを落としていた（今は別名として通る）
10. **呼び出しの答えを退避リストに載せていなかった。** 同じ式の中で 2 回呼ぶと、
   **呼び先が同じ名前のテンポラリを書いて左側の答えを潰す。** `fib(n-1) + fib(n-2)` が
   静かに誤った値を返していた。`factorial` は 1 文 1 呼び出しなので通っていた。
   **M9-10 の作業中に、宛先駆動の安全条件を考えていて気付いた**
11. **文字列の比較をレジスタ経由にしていた。** `execute if data` はそれ自体が条件なので、
   `if` の中では 1 コマンド無駄になっていた。大きい例に書いて生成物を読んで気付いた

**教訓は AGENTS.md の「Things that have already caught people out」に集約してある。**

## 作業の型

```
仕様の該当節を確定させる  →  失敗するテストを書く（落ちるのを見る）
                          →  通す  →  mise run ci && git commit
                          →  03-plan.md のチェックボックスと集計を更新
```

- コミットは 1 タスク 1 コミット。仕様 + 実装 + 進捗更新は同一コミット（AGENTS.md の DoD）
- **`mise run ci && git commit` と繋ぐ。** 並べて書くと CI 失敗でも commit が通る（2 回やった）
- push 前に `mise run ci` の終了ステータスを見る。出力の grep では lint 失敗を見落とす

## 環境

- `mise install` → rust（rustfmt/clippy 込み）と cargo-insta
- `mise run test` / `lint` / `ci` / `snap`
- CI は GitHub Actions（mise-action + `Swatinem/rust-cache`）、push と PR で走る
- toolchain 置き場は `MINEWELL_HOME` で変更可。テストは各自の一時ディレクトリを使う
- 例の toolchain は `examples/toolchains/1.21.4/`（手書きの `commands.json`）。
  手で試すときは `cd examples/arena && MINEWELL_HOME=.. mwl build`

**ローカルの `mise run ci` が通っても CI が落ちることがある。** mise の `rust = "stable"` は
CI では毎回その時点の stable を入れるのに対し、手元は rustup 管理の版を指していることがあり、
**clippy の新しい lint だけ CI で出る**（実際に `question_mark` で 1 回落とした）。
push 後は `gh run list` を見るまでが 1 セット。
